# RAGFlow 基本使用指南

从工作空间和模型配置开始，逐步完成知识库构建、检索验证与 AI 应用创建。本文档适用于当前二次开发版本。

[创建知识库](/datasets) · [配置模型](/user-setting/model)

![RAGFlow 首页展示当前账号可见的工作空间配额、知识库和应用](/help/home-overview.webp)

## 快速开始 {#quick-start}

RAGFlow 的基本链路是：选择资源归属，准备模型，导入并解析知识，创建应用，最后开始问答。

```help-flow
workspace | 选择空间 | 确定资源归属于个人还是团队
model | 配置模型 | 准备聊天、嵌入和解析所需模型
knowledge | 导入知识 | 上传文件并等待解析完成
application | 创建应用 | 绑定同一工作空间的知识库
use | 开始使用 | 在网页或 API 中发起问答
```

> **建议：** 第一次使用时先完成模型配置，再创建知识库。知识库至少需要一个可用的嵌入模型。

## 工作空间 {#workspace}

工作空间决定资源归属、可见范围和可引用关系。创建资源前，请先检查顶栏当前选择的空间。

![在顶栏选择全部、个人或团队工作空间](/help/workspace-selector.webp)

### 个人工作空间

- 用于个人模型、知识库和应用。
- 资源默认仅本人及超级管理员可见。
- 适合草稿、实验或私人资料。
- 资源所属标签显示为 `个人-{创建者}`。

### 团队工作空间

- 用于团队共享知识和应用。
- 团队成员可以看到共享资源，具体修改能力取决于资源类型和团队角色。
- 资源所属标签显示为 `团队-{团队名称}`。

> 顶栏中的“全部”会展示当前账号有权访问的所有空间。创建资源时仍需明确选择一个具体工作空间。

## 模型配置 {#models}

知识库至少需要嵌入模型，聊天和智能体通常还需要聊天模型；PDF 使用 MinerU 解析时还需配置 MinerU 服务。

![在个人中心的模型提供商页面配置默认模型和可用提供商](/help/model-settings.webp)

当前版本提供以下模型提供商：

- **MinerU**：用于 PDF 等文档解析，可选填写 API Key。
- **OpenAI-API-Compatible**：用于兼容 OpenAI API 的聊天、嵌入等模型，服务地址应包含 `/v1`。
- **Xinference**：用于接入 Xinference 中部署的模型。

### 推荐配置顺序

1. 在顶栏选择需要配置模型的个人或团队工作空间。
2. 打开[模型提供商](/user-setting/model)。
3. 选择提供商并填写服务地址、模型名称和可选密钥。
4. 点击“验证”，确认服务可以访问；验证超时为 30 秒。
5. 设置默认聊天模型和嵌入模型。

> 管理后台配置的共享模型默认可供所有工作空间使用；用户也可以在个人空间中添加私有模型。

## 知识库 {#knowledge}

知识库把原始文件解析为可检索分块。应用只有在知识库解析完成并且位于同一工作空间时才能稳定引用。

![知识库列表展示名称、文件数和所属工作空间](/help/dataset-list.webp)

### 创建和解析

1. 打开[知识库](/datasets)，点击“创建知识库”。
2. 选择工作空间、嵌入模型和合适的分块方法。
3. 进入知识库文件列表，点击“新增文件”。
4. 上传完成后启动解析，并等待状态变为解析完成。
5. 在“检索测试”中输入真实问题，检查召回内容和相似度。

![知识库文件列表可上传文件、查看解析状态并进入检索测试或配置](/help/dataset-files.webp)

### 如何选择分块方式

- 通用文档优先使用 **General**。
- 问答对、表格、论文、书籍等结构明确的材料，选择对应的内置分块方法。
- 调整分块参数后，应使用检索测试验证实际召回效果。

> **重要：** 文件显示“解析完成”前不要急于创建问答应用。解析失败时先检查解析状态、模型连通性和文件格式。

## AI 应用 {#applications}

应用可以引用同一工作空间中的共享资源。团队应用由团队成员协作使用和维护。

```help-apps
chat | 聊天 | 将知识库、提示词和聊天模型组合成多轮问答助手，可在网页或兼容 API 中调用 | /chats
search | 搜索 | 面向检索场景快速查找知识内容，适合资料查询、证据定位和结果聚合 | /searches
agent | 智能体 | 通过可视化流程组合模型、知识库、工具、记忆和条件节点，处理复杂任务 | /agents
memory | 记忆 | 保存可复用的长期信息，为聊天或智能体提供跨会话上下文 | /memories
```

### 创建应用时的检查项

1. 应用和所引用的知识库位于同一工作空间。
2. 当前工作空间拥有可用的聊天模型或嵌入模型。
3. 知识库文件已经解析完成。
4. 团队成员仍拥有该团队的访问权限。

## 权限说明 {#permissions}

界面是否允许保存、删除或配置资源，由资源所属空间、资源类型和当前角色共同决定。

| 角色 | 个人资源 | 团队知识库与文件 | 团队聊天、搜索、智能体与记忆 |
| --- | --- | --- | --- |
| 团队普通成员 | 管理自己的资源 | 查看、检索和引用 | 团队成员共同读写 |
| 团队管理员 | 管理自己的资源 | 管理团队全部资源 | 管理团队全部应用和会话 |
| 超级管理员 | 管理所有个人资源 | 管理所有空间资源 | 管理所有应用和会话 |

> 只读用户进入配置页面时，保存按钮会保持禁用并显示原因。不要通过手工修改请求参数绕过界面权限。

## 常见问题 {#troubleshooting}

### 提示 `Provider not found`

确认模型实例仍然存在、模型类型正确，并且当前资源所在工作空间有权使用该模型。

### 文件上传后无法检索

进入知识库文件列表检查解析状态。若失败，请检查 MinerU 或嵌入模型连通性后重新解析。

### 应用中找不到知识库

应用只能引用同一工作空间内的资源。检查两者所属标签，并确认当前账号仍是团队成员。

### 文件无法继续上传

检查首页工作空间配额。达到文件数或存储上限后，需删除无用文件或联系管理员调整配额。

### 仍然无法解决

记录发生时间、操作账号、工作空间、资源 ID 和完整错误信息，并联系系统管理员。
